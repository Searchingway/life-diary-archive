# 项目全局规则：人生档案 / Life Diary

## 项目概述

- 本项目是**本地优先的个人记录应用**，包含桌面端（Windows）和安卓端。
- 所有数据存储在本地 `data/` 目录，无云端同步。

## 目录结构要点

| 路径 | 说明 |
|---|---|
| `src/life_dairy/` | 桌面端核心 Python 源码 |
| `android/` | 安卓端项目（`android/LifeDiaryMobile/`） |
| `data/` | **真实用户数据**，禁止移动、清理、格式化、修改 |
| `packaging/` | 打包脚本（Windows 安装包等） |
| `android_release.keystore` | **APK 签名密钥**，禁止删除、禁止提交 Git |
| `docs/` | 项目文档 |
| `docs/test/05_测试清单.md` | 测试清单 |
| `HANDOFF.md` | 项目交接/状态记录 |
| `TODO` | 待办事项 |

## 红线规则

1. **禁止无理由重构** `src/`、`android/`、`packaging/`。
2. **禁止移动/清理/格式化/修改** `data/` 下的任何文件。
3. **禁止删除或提交** `android_release.keystore`（已在 `.gitignore` 中排除）。
4. **禁止将数据、构建产物、凭据提交到 Git**。

## 工作流程

### 每轮任务前——定位影响范围

先回答：
- 本次改动的触发入口在哪里？
- 会影响到哪些模块？（桌面端 / 安卓端 / 共享数据 / 导出分享 / 文档）
- 涉及哪些文件？（代码 / 配置 / 文档 / 资源）
- 是否需要更新文档？

### 每轮任务后——输出摘要

必须在回复末尾输出：

```
## 修改文件
- path/to/file — 原因

## 测试步骤
1. ...

## 风险
- 说明已考虑的风险和回退方案
```

### 文档同步规则

- **新功能或重要修复**：必须同步更新 `HANDOFF.md`、`README.md`、`TODO` 或 `docs/test/05_测试清单.md`。
- 小改动（纯注释、排版、README 错别字）不需同步，但要在摘要中说明。

## 测试诚实规则

- 不要写"已全面测试"或"已通过所有测试"——实际没跑就是**待验证**。
- 明确写出哪些测试实际执行了，哪些只是理论上应该跑。
- 桌面端测试：`python -m pytest tests/ -v --tb=short`
